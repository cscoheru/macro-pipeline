Generated by `/plan-eng-review` on 2026-08-23

Framework: `pytest`（仓库现有 `requirements-dev.txt`）

## 1. Affected Interfaces

- CLI `preflight`：验证配置、数据根和 yt-dlp 能力，不写业务数据。
- CLI `catalog`：编目频道各 tab，保存/刷新元数据和运行结果。
- CLI `fetch-captions`：发现字幕、确定性选择、下载、最小解析并冻结 raw。
- CLI `status --json`：返回任务状态、版本和最近错误。
- CLI `coverage --json|--markdown`：返回频道/字幕覆盖对账。
- SQLite migration/state store：只操作独立研究库。
- yt-dlp subprocess adapter：唯一网络/外部进程边界。

- file over configured byte limit；

## 4. Database and Filesystem Invariants

1. Empty DB migrates to latest; second migration is no-op with identical schema-version rows.
2. `PRAGMA foreign_keys=ON` is verified on every production connection.
3. `raw_caption.video_id` unique; UPDATE and DELETE fail via triggers.
4. First successful freeze stores exactly one SHA/path/track; repeated calls do not change row, file bytes or mtime.
5. Two simultaneous processes freezing the same video result in one winner and one `already_frozen` result, without traceback or second raw file reference.
6. Crash after raw file rename but before DB commit leaves at most an unreferenced content-addressed file; rerun verifies/reuses it and inserts one row.
7. Crash while writing temp data leaves no referenced incomplete file; stale temp cleanup is bounded to the configured temp namespace.
8. Existing content-addressed path with mismatched bytes is a hard integrity failure, never overwritten.
9. Reading a registered raw whose bytes no longer match SHA produces `raw_integrity_error` and stops derived work.
10. Tests point data root at `tmp_path` and never touch the real `data/store.db`.

## 5. Fake yt-dlp Integration Harness

Use a fixture executable or injected process runner that exercises the actual argv construction and result parser, not only a mocked Python return value. It must be configurable to emit stdout/stderr, exit codes, delays and files.

Required assertions：

- `shell=False`/argv list；
- no title/description is present as a path component or command fragment；
- timeout terminates the child and records retryable timeout；
- stderr is truncated/redacted；
- nonzero exit classes map to missing/auth/unavailable/retryable/tool error where evidence allows；
- media download flags are never present, subtitle-only flags are present；
- frozen row short-circuits before invoking the fake process；
- output file discovery is constrained to the designated temp directory。

## 6. Offline End-to-end Flow

One default test must execute the user-visible flow against `tmp_path` and fake yt-dlp：

```text
preflight
  -> catalog three tabs (one duplicate)
  -> coverage shows pending
  -> fetch one manual, one auto, one missing
  -> immediate rerun
  -> status/coverage JSON
  -> assert two frozen + one missing
  -> assert zero second downloads for frozen videos
  -> assert zero media files and zero macro DB access
```

This is an integration/E2E test even though it has no browser UI.

## 7. Failure-mode Matrix

| Production failure | Test required | Handling required | Operator-visible result |
|---|---|---|---|
| yt-dlp missing/old | preflight fixture | no business write | named configuration error + remediation |
| one channel tab fails | multi-tab integration | retain successes, mark partial | failed tab and reason in coverage |
| YouTube timeout/rate limit | fake delay/exit | retryable + backoff metadata | status shows retryable, not missing |
| video private/deleted | fixture | permanent availability state | item counted separately |
| no Chinese caption | fixture | no retry storm | caption_missing count |
| malformed/empty caption | fixture | try next candidate or fail unfreezed | candidate errors visible |
| two workers race | multiprocessing/integration | one DB winner | loser returns already_frozen |
| disk full/write error | injected filesystem failure | no DB reference | actionable IO error |
| crash between file and DB | fault injection | harmless orphan/reuse | rerun succeeds |
| raw file later corrupted | byte mutation test | hard stop | raw_integrity_error |
| status query on large fixture | generated fixture | SQL aggregate/bounded output | completes under a documented local threshold |
| hostile external text | security fixture | no shell/path/render control | stored as inert data or rejected |

No row in this matrix may have both “no test” and “no error handling”. Silent failures are release-blocking.

## 8. Performance Checks

Use a generated offline corpus of at least 1,000 metadata rows and 1,000 task states：

- catalog upsert is batched/per-video transactional as designed, without a single unbounded lock；
- `status` and `coverage` do not issue per-video queries；
- JSON output size is aggregate-bounded；
- memory does not scale with total subtitle corpus when only metadata/status is requested；
- indexes exist and `EXPLAIN QUERY PLAN` avoids full scans on primary pending/status lookups, except deliberate aggregate scans on the small corpus。

Do not invent a millisecond pass/fail number that depends on hardware. Record an observed baseline and fail only on algorithmic/query-plan regression until the project has stable CI hardware.

## 10. PR-3 LLM Eval Requirement

PR-3 changes prompt/schema/model behavior and therefore requires both deterministic validation tests and an eval corpus：

- gold set includes at least 2 documents and 4 timestamped videos covering causal, predictive, normative and interpretive material；
- score atomicity, source completeness, quote exactness, attribution, layer separation and proposed-concept discipline；
- hard metrics `source completeness`, `quote exactness` and `layer contamination` must be 100%, 100%, 0 respectively for formal outputs；
- semantic extraction precision/recall is reported against a small human-reviewed set; initial threshold must be agreed before auto-scaling；
- prompt/model version changes compare against the stored baseline and never overwrite it。

Real-model eval is explicit and cost-bearing; fake-provider tests remain default.

## 11. Optional Live Smoke

Live smoke is not part of default `pytest` and must require explicit network intent. Use 1–3 public video IDs documented in the implementation handoff, then verify：

- channel/subtitle discovery succeeds with the installed yt-dlp version；
- one Chinese caption freezes；
- immediate rerun short-circuits；
- no audio/video extension exists under data root；
- command output does not expose signed subtitle URLs, cookies or secrets。

Live failure caused by upstream changes is diagnostic evidence, not automatically a unit-test failure. Claude Code must still classify whether the failure is tool drift, authentication, rate limit or implementation defect.
